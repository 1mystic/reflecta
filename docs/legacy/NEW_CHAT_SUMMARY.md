## THE PROBLEM

Predict the top-3 ranked answers for 5-option MCQs (A–E). Evaluated by MAP@3:
- Correct answer at rank 1 → 1.000 pts
- Correct answer at rank 2 → 0.500 pts  
- Correct answer at rank 3 → 0.333 pts
- Not in top 3 → 0.000 pts

Train: 2000 rows. Test: 500 rows.

## WHAT WAS DISCOVERED (GROUND TRUTH ABOUT THE DATASET)

### Fact 1: There are only 252 unique core questions in training (not 2000)

Every prompt wraps a core question inside boilerplate:
```
"Pick the best possible answer: {core_question} among the listed options."
"Which of the following is correct? {core_question} from the following choices."
```

After stripping all prefixes/suffixes, there are **252 unique core questions**, each appearing an average of **7.94 times** in training. **All duplicate rows for the same core question have the identical correct answer label — zero conflicts in 2000 rows.**

### Fact 2: 100% of test rows match a training core question (exact string match)

The 500 test rows map to **228 unique core questions**. Every single one appears in training. This dataset was generated by asking the same questions multiple times with different boilerplate wrappers.

### Fact 3: The test has its own repeat structure

| Test group size | Unique core_q | Test rows |
|-----------------|---------------|-----------|
| 1 (appears once) | 75 | 75 |
| 2 (appears twice) | 75 | 150 |
| 3 | 45 | 135 |
| 4 | 25 | 100 |
| 5 | 8 | 40 |

**We are making 228 unique rank-1 decisions for 500 rows.** Same core_q → same rank-1 prediction for every row in that group (since options are usually identical too). This means errors are correlated in blocks: get one question wrong → wrong on all 2-5 rows for it.

### Fact 4: The score ceiling math

MAP@3 = 0.7520 means 376.0 total points from 500 questions. Since rank-2/3 tweaks (v8, v9, v10 all changed 50-134 predictions) produced near-zero net effect (all landed within ±0.002 of each other), **almost all our score comes from rank-1 correctness**. Working backward:

If rank-2/3 contribute ~0 net: we need ~376 rank-1 correct out of 500.  
→ **~75.2% rank-1 accuracy** = approximately 376 correct rank-1 predictions.  
→ **~124 rank-1 predictions are wrong** across 500 test rows.  
→ Since test has 228 unique decisions: **roughly 52-57 unique questions have wrong rank-1.**

### Fact 5: Label-majority retrieval is PERFECT within training (LOO test = 1.0000)

When we do leave-one-out within training duplicate groups, label-majority gets MAP@3 = **1.000 exactly**. Zero conflicts across 1970 pairs tested. The training dataset is internally completely consistent.

**The ~25% error rate on LB is entirely a train→test divergence problem**, not a retrieval algorithm problem.

### Fact 6: Everything we've tried for rank-2/3 is noise

Tried 5 different rank-2/3 strategies:
- v7 (char-sim rank): 0.7493
- v8 (style-LM blend): 0.7480 (−0.0013)
- v9 (full-text sim + discriminative): 0.74812 (−0.00118)
- v10 (majority vote of v7+v8+v9): 0.7520 (+0.0027)

Range across 4 submissions = 0.0040. All rank-2/3 changes are noise-dominated. **The only lever that matters is rank-1 accuracy.**

### Fact 7: Three classical ML models (XGBoost, LightGBM, MLP) have a fundamental blind spot

When all 3 models unanimously disagree with retrieval's rank-1, inspecting the cases reveals they're all **statistical ties in feature space** — not real signals:
- Numeric options (`d = 1.9·10⁻¹²` vs `d = 3.1·10⁻¹²`): all 5 produce identical feature vectors, argmax is arbitrary
- Relational-swap options ("PMF=continuous, PDF=discrete" vs the reverse): identical bag-of-words, argmax is arbitrary

In both cases retrieval (exact-match similarity = 1.000) is correct. Classical ML features **cannot distinguish these cases**. The model that solves this needs to *understand content*, not count word features.

## THE EXACT GAP: WHAT IS WRONG WITH OUR 124 FAILING PREDICTIONS?

We know:
- Train labels are perfectly consistent (LOO = 1.000)
- We match every test question to training (100% hit)
- Our rank-1 = label-majority from training is wrong ~25% of the time

**Hypothesis A — Option text drifts between train and test:**
For ~117 same-option test groups (same core_q, same options), retrieval text-sim already returns label_majority because the options are identical to training. So drift can't explain these. But for ~36 diff-option groups (93 rows), options are slightly paraphrased between training and test versions. Checked: only 1/500 rows change rank-1 from label-majority even with full-text matching. **This hypothesis doesn't scale to 124 errors.**

**Hypothesis B — Training label is sometimes wrong for the test context:**
The most likely explanation: for ~52-57 unique questions, the "correct" answer that the test-set evaluators chose is **different from what appears in our training lookup**. This could be because:
1. The question is genuinely ambiguous and different annotators picked different answers
2. The option TEXT at label-majority's letter in the test is different enough that even though it's "the same question," it's pointing to a subtly different thing
3. The test was drawn from a different distribution of the same questions where certain answers were mapped differently

**What this means:** a model that *reads and understands the question* could identify when the training label is probably wrong for the specific test phrasing, and choose the better option. Retrieval + text-features cannot do this.

Reaching 0.77 from 0.752 requires **+9 MAP points from 500 rows**, approximately:
- Fixing 9 wrong rank-1s in singleton test groups (1 row each → +1 MAP pt each), OR
- Fixing 2-3 wrong rank-1s in size-4/5 test groups (+4-5 MAP pts each), OR

To fix wrong rank-1 predictions without knowing the answers:
1. **Semantic model (BERT/cross-encoder/LLM):** reads the actual question content and independently scores each option on factual correctness — not text similarity to training, but actual understanding. This is the only approach that can identify cases where training's label doesn't match the test's semantics.
2. **LLM API directly:** call Claude/GPT with each question + 5 options, get a ranked prediction independent of training labels. On questions where LLM disagrees with retrieval and has high confidence, override.

**Specifically, to succeed with a semantic model:**
- Need to focus it on the ~52-57 unique questions where we're currently wrong
- The 228 unique decisions have very unequal test-row counts (8 have 5 rows, 25 have 4 rows)
- Flipping one 5-row wrong question = +5 MAP pts = +0.010 LB
- Getting 3 of the 8 five-row questions right that we currently get wrong = +15 MAP pts = +0.030 LB

## CODE PATTERN: HOW TO REPRODUCE CURRENT BEST (v10)

```python
import pandas as pd, numpy as np, re
from collections import Counter
from difflib import SequenceMatcher

INSTRUCTION_PATTERNS = [
    r'^pick the best possible answer:\s*', r'^select the most accurate option:\s*',
    r'^identify the correct statement:\s*', r'^determine the correct option:\s*',
    r'^choose the correct answer:\s*', r'^which of the following is correct\?\s*',
    r'\s*among the listed options\.?\s*$', r'\s*based on the given context\.?\s*$',
    r'\s*from the following choices\.?\s*$', r'\s*among the following choices\.?\s*$',
    r'\s*carefully\.?\s*$',
]
def normalize(p):
    p = p.strip(); changed = True
    while changed:
        changed = False
        for pat in INSTRUCTION_PATTERNS:
            new_p = re.sub(pat, '', p, flags=re.IGNORECASE).strip()
            if new_p != p: p = new_p; changed = True
    return p

def text_sim(a, b):
    # IMPORTANT: no truncation — full text comparison
    return SequenceMatcher(None, str(a).lower(), str(b).lower()).ratio()

# Build lookup
train['core_q'] = train['prompt'].apply(normalize)
test['core_q']  = test['prompt'].apply(normalize)
lookup = {}
for _, row in train.iterrows():
    key = row['core_q'].lower().strip()
    lookup.setdefault(key, []).append((row['answer'], row))

# Rank-1: label_majority from training
# Rank-2/3: majority vote across 3 independent strategies
# Strategy 1 (v7): char-sim + small ML raw blend (W_ml=0.10)
# Strategy 2 (v8): style-LM bigram score blend
# Strategy 3 (v9): full-text sim (already used above)
# Vote: for rank-2/3, take options that appear in majority's top-2

# For each test row:
# 1. key = normalize(prompt).lower()
# 2. label_majority = Counter([e[0] for e in lookup[key]]).most_common(1)[0][0]
# 3. correct_texts = [str(e[1][e[0]]) for e in lookup[key]]
# 4. ret_scores = {l: max(text_sim(ct, test_row[l]) for ct in correct_texts) for l in LABELS}
# 5. rank1 = label_majority (DO NOT OVERRIDE with text-sim; LOO shows label_majority = perfect)
# 6. rank2/3 = majority-vote ordering of remaining 4 options
```

## WHAT NOT TO DO (LEARNED THE HARD WAY)

1. **Don't trust random 80/20 validation**: training has 7.94 copies per core_q → val set leaks heavily through the lookup, giving 0.92-0.98 val MAP@3 vs 0.73-0.75 on LB. **Use LeaveOneGroupOut/GroupKFold by core_q** or treat LB as ground truth.

2. **Don't add ML blend to rank-1 decisions**: text-similarity + classical ML features are both blind to the exact cases where we're getting rank-1 wrong (numeric values, relational word-order swaps). Blending them in only adds noise.

3. **Don't override label-majority with text-similarity**: checked exhaustively with char-sim, word-Jaccard, TF-IDF, and 3-model ML agreement. 0/500 cases where overriding would help that we can identify *without* knowing the ground truth. Label-majority from training is already the best possible text-based rank-1.

4. **Don't optimize rank-2/3 without knowing which rank-1 predictions are wrong**: rank-2/3 only matters for the ~25% of questions where rank-1 is wrong. Any rank-2/3 strategy applied to all 500 questions is 75% "noise" (applied to questions already correct at rank-1 where it can't help) and only 25% "signal." The noise dominates.

5. **Don't interpret GroupKFold MAP@3 as a predictor of LB rank-2/3 gains**: GroupKFold puts questions in folds where no retrieval match exists, so the model operates in a fundamentally different regime than rank-2/3 ordering where retrieval already got rank-1 right.
